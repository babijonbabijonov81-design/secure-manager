## Возможности

### Шифрование и защита на виду

- **Сквозное шифрование по протоколу Signal**: обмен ключами X3DH и Double Ratchet. Каждое сообщение шифруется собственным ключом, поэтому даже украденный ключ не раскроет прошлую переписку.
- **Сервер ничего не знает.** Ретранслятор хранит только зашифрованные конверты и удаляет их после доставки. Сообщения знакомым уходят по отдельному соединению без входа в аккаунт (sealed sender с ключом доставки), поэтому сервер не знает, от кого они. Реальную длину сообщения скрывает выравнивание.
- **Щит чата** — что защищает переписку прямо сейчас, оценкой «N из 6»: шифрование, сверка ключа, исчезающие сообщения, защита от скриншотов, IP в звонках, свой или общий сервер.
- **Код безопасности** (12 групп по 5 цифр), **слова-сверка** в звонке и **приглашения veil://** с ключом внутри: подмену ключа видно сразу.
- **Смена ключа** не прячется: чат остаётся, красная строка объясняет, что случилось; можно не отправлять ничего, пока не сверите код.
- **Вуаль** размывает входящие, пока не наведёте курсор. Пока вы показываете экран, она включается сама.

### Сообщения и группы

- Ответы, реакции, альбомы с подписью, файлы до 20 МБ, голосовые, кружки (видео до минуты), свои стикеры, архив.
- **Группы** до 50 человек (Sender Keys): владелец, админы, участники. Сервер не знает ни названия, ни состава группы.
- **Фото и видео «на один просмотр»**, **исчезающие сообщения** от 30 секунд до недели.
- **Отложенная отправка** и **капсула времени** — сообщение откроется в выбранный день.
- **Превью ссылок** делает отправитель, получатель ссылку не открывает.
- **Метаданные удаляются** из фото, PDF и документов Office ещё до шифрования.
- **Поиск по всей переписке** — только на этом устройстве, с фильтрами «Фото», «Файлы», «Ссылки», «Голосовые».
- **Голосовые в текст** — распознавание на этом компьютере (Whisper), модель скачивается только с вашего согласия.

### Звонки

- **Аудио- и видеозвонки**, **показ экрана** (на Wayland — через системный портал PipeWire). Звук и видео шифруются DTLS-SRTP, ключи согласуются внутри сквозного шифрования.
- Шумоподавление, выбор микрофона, динамиков и камеры, режим «Скрывать мой IP в звонках» через TURN.

### «Избранное» и данные на компьютере

- **«Избранное»** — сейф для заметок, паролей, ссылок и файлов, только на этом ПК. **Временные заметки** сгорают через 1, 7 или 30 дней.
- Скопированный пароль стирается из буфера через 30 секунд и не попадает в журнал буфера Windows.
- Всё на диске зашифровано ключом из вашего пароля (scrypt, 128 МиБ). Есть автоблокировка, блокировка вместе с системой и при сворачивании в трей.
- **Быстрый вход по PIN** (ключ — в защищённом хранилище системы), на Mac — по Touch ID, на Linux — по отпечатку пальца.
- **Аварийный пароль** открывает пустой Veil, **скрытые чаты** открываются секретной фразой и PIN.
- **Журнал безопасности** с кнопкой «Это не я», **Устройства** с кнопкой «Отключить».
- **Мост** — перенос аккаунта на другой ПК по локальной сети, **резервная копия .veil** — весь аккаунт в одном зашифрованном файле.
- **Двухфакторная аутентификация** (Google Authenticator) и **восстановление по почте**.
- **Смена имени пользователя** в настройках, если новое @имя свободно.
- **Два аккаунта на одном устройстве**: переключение на экране входа, у каждого свой пароль, PIN и отпечаток; выход из аккаунта с проверкой пароля.
- **Копия в OneDrive** — раз в день зашифрованный `.veil` в папку Veil в вашем OneDrive, восстановление через «Войти через Microsoft». Microsoft видит только зашифрованный файл ([подробнее и настройка](docs/ONEDRIVE.md)).

## Установка

Готовые сборки лежат в разделе [**Releases**](https://github.com/babijonbabijonov81-design/secure-manager/releases). Их собирает GitHub Actions, к каждому выпуску приложен файл `SHA256SUMS.txt`.

### Windows 10 (21H2+) и 11

| Файл | Что это |
| --- | --- |
| `Veil-<версия>-win-x64-setup.exe` | установщик для обычных ПК, обновляется сам |
| `Veil-<версия>-win-arm64-setup.exe` | установщик для ПК на ARM (Snapdragon), обновляется сам |
| `Veil-<версия>-win-x64.zip`, `…-win-arm64.zip` | portable-версия без установки: распакуйте и запустите `Veil.exe` |

Сборка не подписана платным сертификатом, поэтому при первом запуске Windows SmartScreen может предупредить о неизвестном издателе. Нажмите **«Подробнее» → «Выполнить в любом случае»**.

### Linux (Ubuntu 22.04+, Debian 12, Fedora 39+, Arch; X11 и Wayland)

| Файл | Как установить |
| --- | --- |
| `Veil-<версия>-linux-x86_64.AppImage` | `chmod +x Veil-*.AppImage && ./Veil-*.AppImage` — работает везде, обновляется сам |
| `Veil-<версия>-linux-amd64.deb` | Ubuntu, Debian: `sudo apt install ./Veil-*.deb` |
| `Veil-<версия>-linux-x86_64.rpm` | Fedora: `sudo dnf install ./Veil-*.rpm`, openSUSE: `sudo zypper install ./Veil-*.rpm` |
| `Veil-<версия>-linux-x86_64.flatpak` | `flatpak install --user ./Veil-*.flatpak` |

На Arch удобнее всего AppImage. Ссылки `veil://` открываются в Veil во всех вариантах: пакеты регистрируют их сами, AppImage — при первом запуске.

### Проверка файлов

Сравните контрольную сумму скачанного файла с `SHA256SUMS.txt` из того же выпуска:

```bash
sha256sum -c SHA256SUMS.txt --ignore-missing     # Linux
```

```powershell
Get-FileHash .\Veil-2.0.0-win-x64-setup.exe      # Windows, PowerShell
```

### Обновления

Veil проверяет новые версии при запуске и раз в шесть часов; вручную — **Настройки → О Veil → Проверить сейчас**.

- Установщик Windows и AppImage скачивают и ставят обновление сами.
- `.deb`, `.rpm` и Flatpak обновляются через менеджер пакетов: Veil покажет «Обновите через менеджер пакетов» и готовую команду для нового пакета.
- Portable-версия даёт ссылку на страницу загрузки.

Переписка при обновлении не теряется: она хранится отдельно от программы.

### macOS 13 и новее (Apple Silicon и Intel)

| Файл | Что это |
| --- | --- |
| `Veil-<версия>-mac-arm64.dmg` | для Mac на Apple Silicon (M1–M4) |
| `Veil-<версия>-mac-x64.dmg` | для Mac с процессором Intel |
| `Veil-<версия>-mac-arm64.zip`, `…-mac-x64.zip` | то же приложение без образа диска |

Откройте `.dmg` и перетащите Veil в «Программы». У приложения нет платной подписи Apple (Developer ID), поэтому при первом запуске:
**правый клик по Veil → «Открыть» → «Открыть»**. На macOS 15 и новее: **Системные настройки → Конфиденциальность и безопасность → «Всё равно открыть»**.

Если macOS пишет, что «приложение повреждено», выполните в Терминале:

```bash
xattr -cr /Applications/Veil.app
```

На Mac работает всё то же, что на Windows и Linux, плюс **вход по Touch ID** и защита окна от снимков экрана. Камера, микрофон, показ экрана и поиск второго компьютера для «Моста» попросят разрешения macOS при первом использовании. Обновления: Veil сообщит о новой версии и откроет страницу загрузки — без подписи Apple приложение не может обновить себя само.

## Как начать общаться

Сообщения передаёт небольшой сервер-ретранслятор, и вы с собеседником должны быть подключены к одному и тому же. Прочитать переписку сервер не может, поэтому его может запустить кто угодно.

### Вариант 1. Одна сеть Wi-Fi: без настройки

1. На одном компьютере на шаге «Подключение к серверу» включите **«Свой сервер на этом компьютере»**. Появятся адреса вида `192.168.1.10:8787`.
2. На втором компьютере в поле «Адрес сервера» укажите этот адрес.
3. Если Windows спросит про брандмауэр, разрешите доступ в частных сетях.

### Вариант 1½. Сервер на своём компьютере — для друзей из любой сети

1. Включите **«Свой сервер на этом компьютере»** (шаг «Подключение к серверу» или **Настройки → Сервер**).
2. Включите **«Доступен из интернета»** и укажите **публичный ретранслятор** — например, ваш сервер на Render из варианта 2. Veil сам попробует:
   - открыть порт на роутере (UPnP, PCP или NAT-PMP) и проверить его снаружи;
   - если провайдер не даёт белый IP (CGNAT) или роутер не открывает порты — поднять **туннель** через ретранслятор (адрес вида `wss://…/t/<id>/ws` не меняется);
   - или взять ваш собственный адрес (домен, IP с пробросом вручную, ngrok, cloudflared).
3. Нажмите **«Скопировать приглашение»** и отправьте ссылку другу. В ней ключ сервера, все адреса и одноразовый токен регистрации: пока сервер открыт в интернет, чужие без приглашения на нём не зарегистрируются.

Что важно знать:

- Пока компьютер выключен или спит, сообщения через этот сервер не ходят. Можно включить «Не давать компьютеру засыпать».
- Публичный ретранслятор видит те же метаданные, что и ваш сервер (кто подключён и сколько весят конверты), но не содержимое: всё шифруется на устройствах, а ключ вашего сервера проверяется сквозь туннель.
- На Windows разрешите Veil в брандмауэре для частных сетей. Сервер слушает все сетевые интерфейсы (`0.0.0.0`).

### Вариант 2. Через интернет: бесплатно на Render

1. Создайте аккаунт на [render.com](https://render.com).
2. **New → Blueprint** и выберите этот репозиторий: Render прочитает `render.yaml` и запустит сервер.
3. Получите адрес вида `https://veil-relay-xxxx.onrender.com` и укажите его в приложении (у себя и у собеседника).

> Ключ сервера на Render задаёт переменная `SERVER_SECRET` (Blueprint создаёт её сам). Без неё ключ меняется при каждом перезапуске, и приложения откажутся подключаться, пока вы не подтвердите новый ключ. Если сервис создан вручную, добавьте в **Environment** `SERVER_SECRET` — любую строку от 32 символов — и `TRUST_PROXY=1`.
>
> Туннели для серверов на домашних компьютерах включены; их число и трафик ограничены переменными `TUNNELS_MAX` и `TUNNEL_MB_PER_DAY`, чтобы не выйти за бесплатные 100 ГБ в месяц. Выключить: `TUNNELS=0`.

> Бесплатный тариф Render засыпает без активности и не хранит данные между перезапусками. Приложения сами зарегистрируются заново, но пропадут сообщения, которые ждали доставки, привязка почты и резервные копии для восстановления. Если восстановление по почте важно, используйте вариант 3 или платный диск на Render.

### Вариант 3. Свой VPS с HTTPS (рекомендуется)

Понадобятся:

- VPS с Ubuntu и публичным IP-адресом (Hetzner, DigitalOcean, Vultr, Timeweb и т. п.; хватит 1 ядра и 1 ГБ памяти);
- домен или поддомен, A-запись которого указывает на IP сервера. Подойдёт и бесплатный поддомен, например на [duckdns.org](https://www.duckdns.org).

1. Установите Docker:

   ```bash
   curl -fsSL https://get.docker.com | sh
   ```

2. Откройте порты. Если на сервере включён брандмауэр ufw:

   ```bash
   ufw allow 80/tcp && ufw allow 443/tcp          # сам сервер Veil (HTTPS)
   ufw allow 3478 && ufw allow 49160:49200/udp    # TURN для звонков (если нужен)
   ```

   У многих провайдеров есть ещё и брандмауэр в панели управления: откройте там те же порты.

3. Скачайте код (пока репозиторий закрытый, git попросит логин и [токен GitHub](https://github.com/settings/tokens)):

   ```bash
   git clone https://github.com/babijonbabijonov81-design/secure-manager veil && cd veil/server
   ```

4. Создайте файл настроек `.env` (например, `nano .env`). Обязателен только `DOMAIN`, остальное по желанию:

   ```ini
   DOMAIN=chat.example.com

   # Звонки через TURN (см. «Звонки и TURN-сервер»). Секрет: любая длинная строка, например из `openssl rand -hex 32`
   TURN_SECRET=вставьте-сюда-длинную-случайную-строку
   TURN_URLS=turn:chat.example.com:3478,turn:chat.example.com:3478?transport=tcp

   # Почта для восстановления аккаунта (см. ниже)
   BREVO_API_KEY=xkeysib-...
   MAIL_FROM=Veil <you@example.com>
   ```

5. Запустите:

   ```bash
   docker compose --profile turn up -d     # сервер + TURN
   docker compose up -d                    # или только сервер, без TURN
   ```

6. В приложении укажите адрес сервера `chat.example.com`. Сертификат HTTPS Caddy получит сам за минуту.

Обновить сервер до новой версии: `git pull && docker compose --profile turn up -d --build`. Журнал: `docker compose logs -f relay`.

Можно обойтись и без Docker: нужен Node.js 22.18+.

```bash
cd server && npm install && PORT=8787 DATA_DIR=./data node src/index.ts
```

### Почта для восстановления аккаунта

Чтобы сервер мог отправлять коды восстановления, задайте ему переменные окружения (на Render: **Environment → Add Environment Variable**, на VPS: в файле `.env`). Подойдёт один из вариантов:

| Переменные | Сервис |
| --- | --- |
| `BREVO_API_KEY` + `MAIL_FROM` | [Brevo](https://www.brevo.com), бесплатно 300 писем в день. Работает на Render, рекомендуется |
| `RESEND_API_KEY` + `MAIL_FROM` | [Resend](https://resend.com), нужен свой домен |
| `SMTP_URL` + `MAIL_FROM` | любая почта по SMTP, например `smtps://you%40gmail.com:пароль-приложения@smtp.gmail.com:465`. На бесплатном Render SMTP-порты закрыты |

`MAIL_FROM` выглядит так: `Veil <you@example.com>`. Адрес отправителя нужно подтвердить в выбранном сервисе. Для проверки без почты запустите сервер с `MAIL_LOG=1`: коды будут печататься в журнал.

Без настроенной почты всё остальное работает, просто кнопка привязки почты сообщит, что сервер не умеет отправлять письма.

### Звонки и TURN-сервер

Звук идёт напрямую между компьютерами (WebRTC). Чтобы найти прямой путь через домашние роутеры, приложение спрашивает свой внешний адрес у публичных STUN-серверов Google и Cloudflare; сам разговор через них не идёт. **Обычно этого достаточно: для звонков ничего настраивать не нужно**, в том числе на Render.

TURN-сервер нужен в двух случаях:

- у кого-то строгая сеть (корпоративная, мобильный интернет, некоторые провайдеры) и звонок «Не удалось соединиться»;
- вы хотите, чтобы собеседник не видел ваш IP (Настройки → Аудио → «Скрывать мой IP в звонках»).

TURN пересылает уже зашифрованный звук и прочитать его не может. На бесплатном Render его не запустить (Render не принимает UDP), нужен VPS из варианта 3: заполните в `.env` строки `TURN_SECRET` и `TURN_URLS` и запустите с `--profile turn`. Ретранслятор сам раздаёт приложениям временные пароли к TURN (на сутки).

Как проверить: в приложении откройте **Настройки → Аудио**. Если у пункта «Скрывать мой IP в звонках» написано «Звук пойдёт через TURN-сервер…», сервер раздаёт TURN.

Если у VPS нет публичного IP прямо на сетевом интерфейсе (AWS, Google Cloud), TURN нужно дополнительно указать внешний адрес; проще выбрать провайдера с обычным публичным IP. Подойдёт и любой другой TURN-сервер: `TURN_URLS` + `TURN_SECRET` (coturn `static-auth-secret`) или `TURN_USERNAME` + `TURN_PASSWORD`. Свои STUN-серверы задаются в `STUN_URLS`.

### Дальше

1. Создайте аккаунт: имя, `@username` и пароль. Пароль шифрует все данные на устройстве, сервер его не знает.
2. Нажмите «Новый чат» и введите `@username` собеседника.
3. Откройте панель «Информация» и сверьте **код безопасности** с собеседником лично или по телефону. Если цифры совпадают, отметьте контакт как проверенный.
4. В **Настройки → Безопасность** включите Google Authenticator и привяжите почту для восстановления.

### Если сменили компьютер или забыли пароль

На экране приветствия нажмите **«У меня уже есть аккаунт — восстановить по почте»**, укажите сервер, `@username` и почту. Введите код из письма (и код из Google Authenticator, если он включён), затем пароль: контакты и переписка вернутся из резервной копии.

Если включена **копия в OneDrive**, нажмите «Восстановить из OneDrive», войдите в тот же аккаунт Microsoft и введите пароль копии.

Если пароль забыт, нажмите «Не помню пароль». Имя `@username` останется за вами, но будут созданы новые ключи, а старую переписку расшифровать уже не получится. Собеседники увидят, что ваш код безопасности изменился.


## Что видит сервер, а что нет

| | Сервер |
| --- | --- |
| Текст сообщений, фото, файлы, голосовые, кружки | ❌ не видит: шифруются на устройстве |
| Ваше имя и список контактов | ❌ не видит: имя передаётся внутри шифра, контакты хранятся только у вас |
| Кто отправил сообщение знакомому | ❌ не видит: конверт уходит по соединению без входа в аккаунт, с ключом доставки, который знают только ваши контакты |
| Кто отправил первое сообщение незнакомцу | ✅ видит: у незнакомца ещё нет вашего ключа доставки, конверт уходит из вашего аккаунта. Так же уходят служебные запросы: поиск по @имени, предключи |
| Точная длина сообщения | ❌ скрыта выравниванием Padmé |
| Реакции, ответы, удаление, «в сети» | ❌ не видит: это тоже зашифрованные сообщения |
| Группы: название, состав, роли | ❌ не видит: каждый участник получает отдельный конверт, состав рассылается внутри шифра |
| Превью ссылок, капсулы, отложенные сообщения | ❌ не видит: превью делает отправитель и шлёт зашифрованным, отложенное до отправки лежит только у вас |
| Звонки, видео, показ экрана | ❌ не слышит и не видит: DTLS-SRTP, ключи согласуются внутри сквозного шифрования |
| Перенос через «Мост», резервная копия .veil | ❌ всё зашифровано: «Мост» — ключом из обмена с кодом сверки, копия — вашим паролем копии |
| Поиск, расшифровка голосовых | ❌ ничего не уходит с компьютера |
| Почта для восстановления | ❌ хранит только HMAC-хэш адреса с секретом сервера |
| Имена ваших устройств | ❌ хранятся зашифрованными, сервер видит только идентификаторы |
| Включена ли 2FA | ✅ видит: секрет Google Authenticator хранится на сервере, чтобы проверять код при восстановлении |
| `@username` и публичные ключи | ✅ видит: нужны, чтобы вас можно было найти |
| Кому адресован конверт и когда | ✅ видит: иначе конверт нельзя доставить |
| IP-адрес подключения | ✅ видит, как любой интернет-сервис (скрыть его можно через VPN или Tor). Анонимное и обычное соединение идут с одного адреса, так что по IP и времени их можно сопоставить |

Для каждой функции, которая что-то отправляет, есть тест «сервер видит только шифр»: он перехватывает все кадры ретранслятора и ищет в них исходный текст. Подробное описание протокола и схемы угроз — в [docs/SECURITY.md](docs/SECURITY.md).

## Ограничения

- Один аккаунт работает на одном компьютере: «Мост» и восстановление переносят аккаунт, а не дублируют его.
- Установщик Windows не подписан сертификатом (Authenticode), приложение для Mac — Developer ID Apple, пакеты Linux — ключом GPG; проверяйте файлы по SHA-256.
- **На Linux нет надёжной защиты от скриншотов** — Щит чата так и пишет. Windows Hello пока не поддерживается, быстрый вход — по PIN.
- В группах пока нет звонков, реакций, исчезающих сообщений, капсул, фото «на один просмотр» и отчётов о прочтении.
- Расшифровка голосовых есть только в приложении для ПК: модель хранится в его папке.
- При прямом звонке собеседник видит ваш IP-адрес, как в любом P2P-звонке. Скрыть его можно только через TURN-сервер (см. «Звонки и TURN-сервер»).
- Независимого аудита безопасности не было. Используются проверенные библиотеки [noble](https://paulmillr.com/noble/) (прошли аудит), но сам код мессенджера никто не аудировал.

## Разработка

Нужен Node.js 22.18+ (рекомендуется 24).

```bash
npm install
npm run dev          # приложение в режиме разработки
npm run server       # отдельный сервер на :8787
npm run web          # интерфейс в браузере (?profile=имя для нескольких аккаунтов)

npm run typecheck
npm test             # криптография, сервер, движок и тесты «сервер видит только шифр»
npm run test:e2e     # пользователи переписываются в браузере (Playwright)
npm run build && xvfb-run -a node tests/electron/smoke.mjs   # проверка собранного приложения

npm run dist:win     # установщики и .zip для Windows x64 и ARM64 (на Linux нужен wine)
npm run dist:linux   # AppImage, .deb, .rpm (нужен rpmbuild) и Flatpak (нужен flatpak-builder)
npm run dist:mac     # .dmg и .zip для Apple Silicon и Intel (только на macOS)
```

Два аккаунта на одном компьютере удобно запускать через профили: `Veil --profile=test` или переменную `VEIL_PROFILE=test`. Для проверки восстановления запускайте сервер с `MAIL_LOG=1`. Сервер по умолчанию пускает не больше 20 новых аккаунтов в час с одного IP; для тестов это меняется переменной `REGISTRATIONS_PER_HOUR`. Если перед сервером стоит прокси (Render, Caddy, nginx), задайте `TRUST_PROXY=1`: тогда адрес клиента берётся из `X-Forwarded-For`, иначе этот заголовок игнорируется, ведь подделать его может кто угодно.

Скриншоты для этого файла снимаются автоматически в обеих темах:

```bash
SCREENSHOTS=docs/screenshots npx playwright test tests/e2e/screenshots.spec.ts
```

### Выпуск версии

```bash
npm version 2.0.1
git push --follow-tags
```

Можно и без терминала: на GitHub откройте **Actions → Build desktop apps → Run workflow**, поставьте галочку **release** и нажмите **Run workflow**. Версия берётся из `package.json`, описание выпуска — из раздела этой версии в `CHANGELOG.md`.

Поле **platforms** позволяет выпустить версию по частям. Если выбрать `windows`, выйдет предварительный выпуск только с Windows: можно проверить его до остальных, а программы на macOS и Linux его не увидят. Если затем выбрать `mac-linux`, в тот же выпуск добавятся macOS и Linux, `SHA256SUMS.txt` объединится, и выпуск станет основным.

GitHub Actions прогонит тесты, соберёт Windows (NSIS и .zip, x64 и ARM64), macOS (.dmg и .zip, Apple Silicon и Intel) и Linux (AppImage, .deb, .rpm, Flatpak), посчитает `SHA256SUMS.txt` и опубликует релиз вместе с файлами `latest*.yml`, по которым приложения находят обновление.

> Обновление из приложения читает релизы этого репозитория без авторизации, поэтому репозиторий должен быть **публичным**. Адрес задаётся в `electron-builder.yml` (`publish`) и `src/main/updater.ts`.
